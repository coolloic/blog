# LLM Wiki Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an agent-maintained, Karpathy-style LLM Wiki at `/wiki/` to the existing Hugo/PaperMod blog, seeded from the post "The Anatomy of a Modern AI Agent".

**Architecture:** Wiki pages are plain Markdown under `content/wiki/` (`concepts/`, `sources/`, `_index.md` index, `log.md`). Cross-links are relative `.md` links resolved by Hugo's embedded link render hook, so the folder also works in Obsidian. A root `CLAUDE.md` is the schema defining ingest/query/lint. `raw/` holds private sources and is gitignored. A shell check script is the test suite.

**Tech Stack:** Hugo 0.169 extended, PaperMod (git submodule), bash.

**Spec:** `docs/superpowers/specs/2026-11-13-llm-wiki-design.md`

## Global Constraints

- Repo root: `/Users/loic/Projects/blog`. Do not modify anything under `themes/PaperMod/`.
- Raw sources must never be committed (public repo): `raw/*` ignored except `raw/README.md`.
- Every wiki claim must trace to a page in `content/wiki/sources/`.
- Wiki links: relative Markdown links to `.md` files only (e.g. `[MCP](mcp.md)`, `[Post](../sources/anatomy-of-a-modern-ai-agent.md)`); no `[[wikilinks]]`.
- Do not `git push`. Publishing the agents post and the wiki needs the owner's go-ahead.

## Review Focus

1. **Wiki pages leaking into the home page/archive/post nav.** PaperMod lists `site.Params.mainSections`, which defaults to the largest section, which would soon be `wiki`. Expect: home and archive show only posts. Test in Task 1 (`check_home_posts_only`).
2. **Broken relative link** (typo, renamed page, `../` from a nested folder). Expect: the build fails loudly, not a dead link. Test in Task 1 (`--panicOnWarning` plus a deliberately broken fixture) and Task 3.
3. **Raw file accidentally committed.** Expect: git ignores it. Test in Task 1 (`git check-ignore raw/sample.pdf`).
4. **Page created but missing from the index.** Expect: the check fails and names the page. Test in Task 3 (`check_index_complete`).
5. **Wiki not searchable.** Expect: wiki pages appear in `/index.json`. Test in Task 3 (`check_search_includes_wiki`).

### Task 2: Schema (`CLAUDE.md`)

**Files:**
- Create: `CLAUDE.md`

**Interfaces:**
- Consumes: the folder layout, front-matter convention, link rule and check script from Task 1.
- Produces: the ingest / query / lint workflows that Task 3 follows exactly.

- [ ] **Step 1: Write `CLAUDE.md`** with these sections:
  - **Layout**: the three layers (raw, wiki, schema) and what may be edited (`raw/` never).
  - **Page conventions**: front matter, kebab-case slugs, the link rule, one concept per page, a `## Sources` list at the bottom of each concept page.
  - **Ingest** (numbered): read the file in `raw/` (or a URL or post given by the owner) → create `sources/<slug>.md` (summary, key claims, link to the original) → create or update each affected concept page, citing the source → update `_index.md` (one line per page: link — summary) → append to `log.md` → run `scripts/check-wiki.sh`.
  - **Query**: answer from wiki pages with links to them. If the answer adds lasting value, offer to file it as a concept page and log it.
  - **Lint**: report contradictions, orphans (pages not linked from any other page), concepts mentioned on 2+ pages that lack their own page, claims without a source, and stale `lastmod`. Log the run. Fix only with owner approval.
  - **Blog vs wiki**: posts are dated essays in `content/posts/`; the wiki may cite posts as sources.
- [ ] **Step 2: Verify.** `bash scripts/check-wiki.sh`. Expected: all PASS (`CLAUDE.md` is outside `content/`, so the build is unaffected).
- [ ] **Step 3: Commit.** `git add CLAUDE.md && git commit -m "docs(wiki): add wiki schema and workflows"`
