A knowledge base on cutting-edge AI, maintained by an LLM from sources I collect. Each concept page cites its sources. See the [log](log.md) for what changed and when.

## Concepts

### Forward deployed engineering

- [AI Governance and Compliance](concepts/ai-governance-and-compliance.md): The regulatory and standards layer for enterprise AI: EU AI Act obligations and dates, NIST AI RMF and its GenAI profile, ISO/IEC 42001, SOC 2 assurance, and bank model risk management, with how they fit together.
- [AI Use-Case Discovery](concepts/ai-use-case-discovery.md): How to find, qualify, scope and prioritise LLM use cases in an organisation: where to look, fit tests for LLMs and agents, impact/effort scoring, success metrics and build-vs-buy.
- [Data Retention and Residency](concepts/data-retention-and-residency.md): What zero data retention (ZDR) and data residency actually guarantee on Anthropic, OpenAI, Google (Gemini API and Vertex AI), Azure and Bedrock: which stores survive ZDR, which features break it, how regional processing differs from regional storage, and where DPAs and BAAs fit.
- [Enterprise LLM Deployment](concepts/enterprise-llm-deployment.md): Running LLMs inside an enterprise's security perimeter: data retention and ZDR, residency, identity and RBAC, audit logging, PII handling, network isolation, and how to roll out and drive adoption.
- [Forward Deployed Engineering](concepts/forward-deployed-engineering.md): The forward deployed engineer (FDE) role: a product-grade software engineer embedded with one customer to ship production systems, born at Palantir and now central to how OpenAI, Anthropic and AI startups deploy LLMs.
- [POC to Production](concepts/poc-to-production.md): Taking an LLM proof of concept to a dependable production system: why most pilots stall, the stage gates (evals, guardrails, integration, rollout), human-in-the-loop design, change management and the post-launch data flywheel.

### Models

- [Batch Processing](concepts/batch-processing.md): Asynchronous vendor batch APIs that run large request sets at about 50% off within a 24-hour window: limits, lifecycle, result handling and caching interplay across Anthropic, OpenAI and Gemini.
- [Computer-Use Agents](concepts/computer-use-agents.md): Agents that operate GUIs and browsers through screenshots, mouse and keyboard (Anthropic computer/browser use, OpenAI CUA, Playwright-based agents): the action loop, grounding, benchmarks, reliability, prompt-injection risk and sandboxing.
- [Context window](concepts/context-window.md): The maximum number of tokens a model can attend to in one request (input plus output), what counts against it, vendor limits as of 2026-11, overflow behaviour, and why the usable window is smaller than the advertised one.
- [Extended Thinking](concepts/extended-thinking.md): Claude's API mechanism for visible-but-summarized reasoning: adaptive thinking with effort (current) or a fixed budget_tokens (legacy), thinking blocks with signatures, and interleaved thinking between tool calls.
- [Frontier Model Landscape](concepts/frontier-model-landscape.md): The proprietary frontier model families (Anthropic Claude, OpenAI GPT, Google Gemini, xAI Grok) as of November 2026: tiers, context windows, prices, and how vendors differentiate.
- [Function Calling](concepts/function-calling.md): The API protocol by which a model emits structured requests to run developer-defined tools, and how Anthropic, OpenAI and Gemini differ on schemas, tool choice and parallel calls.
- [Hallucination](concepts/hallucination.md): When an LLM produces fluent output that is false or unsupported: its types, why training makes it inevitable, how to detect it, and how to reduce it.
- [LLM limitations](concepts/llm-limitations.md): The systematic failure modes of LLMs (hallucination, knowledge cutoff, tokenization artifacts, non-determinism, sycophancy, position bias, long-context decay, refusals) with causes and mitigations.
- [LLM Non-Determinism](concepts/llm-non-determinism.md): Why the same prompt at temperature 0 can return different completions: batch-size-dependent kernels, floating-point precision, MoE routing, serving changes and seeds; what each vendor guarantees; and how to engineer around it.
- [Long-context degradation](concepts/long-context-degradation.md): Why LLM accuracy falls as inputs grow and depends on where information sits: lost-in-the-middle, needle-in-a-haystack limits, effective context length and context rot.
- [Mixture of Experts (MoE)](concepts/mixture-of-experts.md): Sparse transformer architecture where a router sends each token to a few of many expert FFNs: compute follows active parameters, memory follows total parameters, and it now underlies almost every large open-weight model.
- [Model Selection](concepts/model-selection.md): How to choose an LLM for a workload: criteria, eval-driven selection, effort tuning before model switching, tier routing and cascades, and cost per completed task.
- [Multimodal Models](concepts/multimodal-models.md): Models that take images, documents and audio as input (and sometimes produce images or speech): how inputs become tokens, per-vendor limits and costs, image generation, speech models, and failure modes.
- [Open-Weight Models](concepts/open-weight-models.md): LLMs whose trained weights you can download and run yourself (Qwen, DeepSeek, Kimi, Mistral, Meta Muse/Llama, Gemma, gpt-oss): architectures, sizes, licences and trade-offs as of November 2026.
- [Prompt Caching](concepts/prompt-caching.md): Reusing the stored KV state of a repeated prompt prefix to cut input cost and latency: mechanics, breakpoints, TTLs and pricing across Anthropic, OpenAI and Gemini.
- [Reasoning Models](concepts/reasoning-models.md): LLMs trained with reinforcement learning to produce a long hidden chain of thought before answering, trading tokens and latency for accuracy on verifiable, multi-step problems.
- [Sampling parameters](concepts/sampling-parameters.md): How temperature, top-k, top-p, min-p, penalties, stop sequences and max tokens shape what an LLM generates, how each vendor exposes them as of 2026-11 (Anthropic removed temperature/top_p/top_k), and why temperature 0 is still not deterministic.
- [Streaming](concepts/streaming.md): Incremental delivery of model output over server-sent events: each vendor's event grammar, how tool calls and thinking stream, mid-stream errors and recovery.
- [Structured Outputs](concepts/structured-outputs.md): Forcing model output to match a JSON Schema via grammar-constrained decoding, how it differs from JSON mode, and each vendor's schema subset, limits and failure modes.
- [Test-Time Compute](concepts/test-time-compute.md): Spending more inference compute per query (longer reasoning, many samples plus selection, search against a verifier) to raise accuracy: a scaling axis separate from model size.
- [Tokenization](concepts/tokenization.md): How LLMs split text into subword tokens (BPE, byte-level BPE, Unigram, WordPiece, SentencePiece), why token counts differ across vendors, models and languages, and how to count them correctly.
- [Transformer architecture](concepts/transformer-architecture.md): How a decoder-only transformer turns tokens into a next-token distribution: embeddings, causal self-attention, feed-forward blocks, positional encoding (RoPE) and the attention variants that make inference affordable.
- [Voice Agents](concepts/voice-agents.md): Agents that converse in real-time speech: cascaded STT-LLM-TTS vs speech-to-speech vs full-duplex architectures, the latency budget, turn detection and interruptions, transports, tool calls and evaluation.

### Prompting

- [Chain-of-thought](concepts/chain-of-thought.md): Prompting a model to generate intermediate reasoning before its answer, plus its extensions (zero-shot CoT, self-consistency, tree of thoughts) and how built-in thinking changed it.
- [Constrained Decoding](concepts/constrained-decoding.md): How grammar- and JSON-schema-constrained generation works inside the decoder (token masks, FSM and CFG compilation, XGrammar, llguidance, Outlines), its real latency and quality costs, provider strict-mode coverage and failure modes.
- [Few-shot prompting](concepts/few-shot-prompting.md): Steering an LLM with a handful of input-output demonstrations in the prompt (in-context learning): how it works, how to pick and format examples, and its biases.
- [Instructor and Outlines](concepts/instructor-and-outlines.md): The two Python approaches to typed LLM output: Instructor validates Pydantic models client-side and re-asks on failure; Outlines constrains generation token by token (or delegates to provider strict modes). Mechanics, modes, costs, failure modes and when to use which.
- [Prompt engineering](concepts/prompt-engineering.md): Designing, structuring, testing and versioning the instructions and inputs an LLM sees in a single call, per Anthropic, OpenAI and Google guidance.
- [System prompts](concepts/system-prompts.md): The privileged, operator-level instructions that frame a conversation: how vendors implement them (system, developer, instructions), their precedence over user turns, what belongs in them, and their limits.

### Retrieval and data

- [Agentic RAG](concepts/agentic-rag.md): RAG where an LLM controls retrieval: deciding whether, what and how often to retrieve, grading results and correcting course; covers routers, corrective RAG (CRAG), Self-RAG, adaptive RAG and just-in-time agentic search.
- [ANN Indexes](concepts/ann-indexes.md): Approximate nearest-neighbour index structures (HNSW, IVF, PQ and other quantizers, DiskANN) that trade a little recall for orders-of-magnitude faster vector search, and how to tune them.
- [BM25](concepts/bm25.md): The Okapi BM25 lexical ranking function: IDF times a saturating, length-normalized term frequency, tuned by k1 and b; the default scorer in Lucene-family engines and the baseline every neural retriever is measured against.
- [Chunking](concepts/chunking.md): Splitting documents into retrievable units for RAG: fixed, recursive, semantic, LLM and late chunking, the size/overlap trade-off, contextual chunk headers, and how to measure chunk quality.
- [Contextual Retrieval](concepts/contextual-retrieval.md): Index-time enrichment that prepends document-level context (an LLM-written blurb or a templated chunk header) to every chunk before embedding and BM25 indexing; Anthropic measured 35-67% fewer retrieval failures.
- [Document Processing](concepts/document-processing.md): Document AI for LLM systems: turning PDFs, scans and office files into structured text with layout detection, OCR and table-structure models (Docling, Unstructured, LlamaParse) or with vision-language models, plus how to choose, evaluate and fail safely.
- [Embeddings](concepts/embeddings.md): Fixed-length vectors from an encoder model that place semantically similar inputs close together; the representation behind semantic search and RAG.
- [GraphRAG](concepts/graphrag.md): RAG over an LLM-built knowledge graph with hierarchical community summaries, built for multi-hop and whole-corpus questions that flat top-k retrieval cannot answer; plus cheaper variants like LazyGraphRAG.
- [Hybrid search](concepts/hybrid-search.md): Combining lexical BM25 and dense vector retrieval and fusing the two rankings, usually with reciprocal rank fusion (RRF) or a weighted score blend.
- [Late-Interaction Retrieval](concepts/late-interaction-retrieval.md): Multi-vector retrieval (ColBERT, ColBERTv2/PLAID, ColPali/ColQwen for page images) that keeps one vector per token or image patch and scores with MaxSim: how it works, what it costs to store, how to scale it, and when it beats single-vector embeddings.
- [Query Transformation](concepts/query-transformation.md): Rewriting the user's question before retrieval (rewriting, expansion, HyDE, multi-query fusion, step-back, decomposition, self-query metadata filters): how each works, what it costs, and when it helps or hurts.
- [Reranking](concepts/reranking.md): A second retrieval stage that re-scores a wide candidate set with a more expensive model (cross-encoder, late-interaction or LLM) to put the truly relevant chunks on top.
- [Retrieval-augmented generation (RAG)](concepts/retrieval-augmented-generation.md): Grounding an LLM's answer in documents fetched at query time: the ingest, retrieve, augment, generate pipeline, its add-ons (query rewriting, HyDE, contextual retrieval), its CAG alternative and how to evaluate it.
- [Text-to-SQL](concepts/text-to-sql.md): Translating natural-language questions into executable SQL with LLMs: schema linking, value retrieval, candidate generation and self-correction, semantic layers as the governed alternative, the Spider/BIRD/Spider 2.0 benchmarks and why their numbers overstate production accuracy.
- [Vector Databases](concepts/vector-databases.md): Systems that store embeddings with metadata and answer filtered nearest-neighbour queries at scale; how pgvector, Pinecone, Weaviate, Qdrant, Milvus and Chroma differ.

### Training and fine-tuning

- [Fine-tuning](concepts/fine-tuning.md): Continuing to train a pre-trained LLM's weights on task data (SFT, preference or RL) to change how it behaves; when to use it versus prompting or RAG, how to prepare data, and how it fails.
- [Knowledge Distillation](concepts/knowledge-distillation.md): Training a small student model to imitate a larger teacher, from Hinton's soft targets to LLM sequence-level, black-box, reasoning and on-policy distillation.
- [LLM Training Pipeline](concepts/llm-training-pipeline.md): How a frontier LLM is produced, stage by stage (data curation, pretraining, mid-training and long-context extension, SFT, preference tuning, RLVR, constitutional and spec-based safety training), and how each stage explains behaviour you see in production.
- [PEFT and LoRA](concepts/peft-and-lora.md): Parameter-efficient fine-tuning: freeze the base model and train a small adapter. How LoRA, QLoRA, DoRA and rsLoRA work, their key hyperparameters, and when they match full fine-tuning.
- [Preference Optimization](concepts/preference-optimization.md): Post-training that pushes a model toward preferred or rewarded outputs: RLHF with PPO, DPO and its variants, GRPO and RL with verifiable rewards, and RLAIF / Constitutional AI.
- [Reinforcement Fine-Tuning](concepts/reinforcement-fine-tuning.md): Post-training an LLM with reinforcement learning against a programmatic or model-based grader (RLVR, GRPO and its variants, managed RFT APIs), which is how reasoning models are trained and how narrow expert tasks are sharpened.
- [Scaling Laws](concepts/scaling-laws.md): Empirical power laws linking LLM loss to parameters, training tokens and compute: Kaplan vs Chinchilla, the ~20 tokens/parameter rule, why production models are deliberately over-trained for cheaper inference, and the limits of extrapolation.
- [Synthetic Data Generation](concepts/synthetic-data-generation.md): Using LLMs to write training and evaluation data (self-instruct, evolution, persona and template prompting, teacher distillation, rejection sampling), plus the filtering, decontamination and licensing work that decides whether it helps or hurts.

### Inference and serving

- [Hugging Face Ecosystem](concepts/hugging-face-ecosystem.md): The Hugging Face Hub and its libraries (transformers, datasets, PEFT, safetensors, huggingface_hub) plus its hosted inference (Inference Providers, Inference Endpoints): what each does, key APIs, model cards and licences, pitfalls.
- [KV Cache](concepts/kv-cache.md): The per-token attention keys and values an LLM stores during generation: how to size it, how engines page and share it (PagedAttention, prefix caching, RadixAttention), and how GQA, MLA and FP8 shrink it.
- [LLM Inference Serving](concepts/llm-inference-serving.md): How LLMs are served at scale: prefill vs decode, latency/throughput metrics, continuous batching, PagedAttention, and the vLLM / SGLang / TensorRT-LLM / TGI engines.
- [Local LLMs](concepts/local-llms.md): Running open-weight models on your own laptop, workstation or server with Ollama, llama.cpp, LM Studio or MLX: how the runtimes work, memory math, key settings, failure modes and when local beats an API.
- [Quantization](concepts/quantization.md): Storing and computing LLM weights, activations and KV cache in fewer bits (FP8, INT8, INT4): how the methods work (GPTQ, AWQ, SmoothQuant, LLM.int8, GGUF), what they cost in accuracy, and which to use where.
- [Semantic Caching](concepts/semantic-caching.md): Serving a stored LLM response when a new prompt's embedding is close enough to a cached one: mechanics, threshold tuning, false hits, invalidation, per-user scoping and side channels, how it differs from prompt caching, and realistic hit rates.
- [Speculative Decoding](concepts/speculative-decoding.md): Cutting decode latency by letting a cheap drafter propose several tokens that the target model verifies in one pass, with a rejection rule that keeps outputs identical in distribution; variants include draft models, n-gram, Medusa, EAGLE and MTP.
- [vLLM](concepts/vllm.md): The open-source LLM serving engine built on PagedAttention: how its V1 engine schedules, caches and parallelizes, what its OpenAI-compatible server does, which flags matter, and how it compares with SGLang and TensorRT-LLM.

### Evaluation and observability

- [Arize Phoenix](concepts/arize-phoenix.md): Source-available, OpenTelemetry-native tracing and evaluation tool: OpenInference span conventions, phoenix-otel setup, structured-output LLM evaluators, datasets and experiments, free self-hosting, and how it compares with Braintrust, Langfuse and LangSmith.
- [Benchmarks](concepts/benchmarks.md): Public LLM benchmarks (MMLU, GPQA, HLE, SWE-bench, τ-bench, ARC-AGI, Arena): what each measures, how it is graded, saturation, contamination, and how to read leaderboards.
- [Braintrust](concepts/braintrust.md): Hosted eval-and-observability platform built around immutable experiments, versioned datasets, reusable scorers and sampled online scoring of production logs; how it works, its architecture, pricing and when to pick it.
- [Cost and Latency Optimization](concepts/cost-and-latency-optimization.md): The levers that cut LLM application cost and latency (prompt caching, semantic caching, batching, routing and cascades, smaller models, token budgets, streaming, parallelism) and their trade-offs.
- [Error Analysis](concepts/error-analysis.md): The practitioner loop of reading LLM and agent traces, open-coding failures in free text, axial-coding them into a counted failure taxonomy, and turning the top categories into targeted evals.
- [Langfuse](concepts/langfuse.md): Open-source, OpenTelemetry-based LLM engineering platform: tracing, prompt management, datasets, experiments, LLM-as-judge and CI gating, self-hostable on Postgres + ClickHouse.
- [LLM Evaluation](concepts/llm-evaluation.md): Designing evals for LLM apps and agents: golden datasets, code, model and human graders, offline vs online, regression suites, statistics and tooling.
- [LLM Observability](concepts/llm-observability.md): Tracing, metrics and feedback for LLM apps and agents: the span data model, OpenTelemetry GenAI conventions, what to log, and how LangSmith, Langfuse and Phoenix differ.
- [LLM-as-Judge](concepts/llm-as-judge.md): Using a language model to grade outputs: pointwise vs pairwise vs reference-guided modes, known biases, calibration against humans, and when not to use it.
- [OpenTelemetry GenAI Semantic Conventions](concepts/opentelemetry-genai.md): The vendor-neutral OTel vocabulary for LLM and agent telemetry: gen_ai.* spans, attributes, events and metrics, opt-in content capture, spec status (still Development, own repo since 2026), the OpenLLMetry and OpenInference dialects, and which backends ingest it.
- [Prompt Management](concepts/prompt-management.md): Treating prompts as versioned, deployable artifacts: registries with immutable versions and movable labels, caching and fallbacks, trace linkage, and the eval-gated promotion loop.
- [promptfoo](concepts/promptfoo.md): Open-source (MIT) CLI and library for declarative LLM evals and red teaming: a prompts × providers × tests matrix scored by assertions, with exit codes that gate CI.
- [RAGAS and DeepEval](concepts/ragas-and-deepeval.md): The two most-used open-source LLM metric libraries: how their faithfulness, relevancy and context precision/recall metrics and G-Eval are computed, and why same-named metrics can disagree.
- [Retrieval Metrics](concepts/retrieval-metrics.md): How to measure a retriever: hit rate, recall@k, precision@k, MRR, MAP, nDCG and RAGAS context precision/recall, what each one rewards, where implementations disagree, and how to build the labelled set they all need.

### Agents

- [Agent design patterns](concepts/agent-design-patterns.md): Reusable architectures for arranging one or many agents, and how to choose between them.
- [Agent guardrails](concepts/agent-guardrails.md): Sandboxing, permissions, hooks and input handling that bound what an agent can do: the sandbox vs approval-policy split, the lethal trifecta and Rule of Two, SDK permission pipelines and their gaps, scoped credentials and egress control.
- [Agent Handoffs](concepts/agent-handoffs.md): Transferring control of a conversation from one agent to another via a transfer tool call, as opposed to calling an agent as a tool; mechanics in OpenAI Agents SDK, LangGraph, ADK and Agent Framework, context passing and failure modes.
- [Agent Instruction Files](concepts/agent-instruction-files.md): Repository and user Markdown files (AGENTS.md, CLAUDE.md, GEMINI.md, Cursor rules) that coding agents load into every session as standing guidance: discovery order, size caps, scoping, and evidence that less is more.
- [Agent loop](concepts/agent-loop.md): The core of every AI agent: a model choosing actions in a loop until the task is done, plus the stop conditions, state rules and limits a production loop needs.
- [Agent Memory](concepts/agent-memory.md): How agents retain information beyond one context window: short-term thread state, long-term episodic/semantic/procedural stores, the write and retrieval pipelines (Mem0, Letta/MemGPT, LangGraph store, Claude memory tool), and how memory fails.
- [Agent Skills](concepts/agent-skills.md): Folders of instructions, scripts and resources (SKILL.md) that an agent discovers by description and loads on demand through progressive disclosure; an open standard read by Claude, Codex, Gemini CLI and Cursor.
- [Code Execution Sandboxes](concepts/code-execution-sandboxes.md): Isolated environments (provider code-interpreter tools, microVM or gVisor sandbox platforms, OS-level sandboxes) that let agents run model-generated code while bounding what it can touch, reach and consume.
- [Coding Agents](concepts/coding-agents.md): LLM agents that read, edit, run and verify code in a real repository through a harness of tools, instructions files and sandboxes (Claude Code, Codex, Cursor, Copilot, Devin).
- [Context Compaction](concepts/context-compaction.md): Replacing older conversation or agent history with a model-written summary as the window fills: client vs server-side implementations (Anthropic, OpenAI), tool-result clearing, context resets, failure modes and how to choose.
- [Context engineering](concepts/context-engineering.md): Deciding what goes into an agent's finite context window, and when.
- [Deep Research Agents](concepts/deep-research-agents.md): Agents that spend minutes to tens of minutes planning, searching the web in parallel, reading, and synthesising a cited report; architecture, vendor implementations (OpenAI, Google, Anthropic, Perplexity), evaluation, cost and failure modes.
- [Durable Agent Execution](concepts/durable-agent-execution.md): Running long-lived agents so they survive crashes, deploys and multi-day waits: journaling model and tool calls, replaying to resume, idempotent side effects, and the Temporal / LangGraph / Inngest / Vercel Workflow / Restate options.
- [Harness Engineering](concepts/harness-engineering.md): Designing everything around an LLM that turns it into a working agent (instructions, tools, environment, context management, orchestration, feedback) and re-tuning that harness as models change.
- [Human-in-the-Loop](concepts/human-in-the-loop.md): Pausing an agent for human approval, editing or input at risky points: durable interrupts, tool approval gates (approve / edit / reject), escalation triggers, reviewer UX and security, and how the major frameworks implement it.
- [Letta](concepts/letta.md): Letta (formerly MemGPT), a platform for stateful agents that manage their own memory: in-context memory blocks or git-backed MemFS files, archival and conversation search, sleep-time/dreaming agents that consolidate memory in the background, and a persistent agent server.
- [Mem0](concepts/mem0.md): Mem0, a drop-in long-term memory layer for agents: an LLM extracts facts from conversations into vector, SQL and entity stores, and retrieval fuses semantic, keyword and entity signals. Covers the 2025 CRUD pipeline, the 2026 ADD-only redesign, graph memory, the benchmark disputes, and Platform vs OSS.
- [Model Context Protocol (MCP)](concepts/model-context-protocol.md): Open standard for exposing tools, resources and prompts to any compatible agent.
- [ReAct pattern](concepts/react-pattern.md): ReAct (Yao et al., 2022): an LLM agent interleaves free-text reasoning with tool actions and their observations; the ancestor of today's tool-calling agent loops.
- [Subagents](concepts/subagents.md): Delegating focused sub-tasks to agents with fresh context windows.
- [Tools](concepts/tools.md): Functions an agent can call to act on the world; their design is interface design for a model: sharp descriptions, lean results, readable errors, a small loaded catalogue and untrusted outputs.
- [Verification and evals](concepts/verification-and-evals.md): Feedback from outside the model, for the agent at runtime and for the builder over time: tests, hooks, critics and citation checks; capability vs regression evals, pass@k vs pass^k, judge biases and online evals.
- [Web Search APIs for Agents](concepts/web-search-apis.md): How agents get live web access: provider-native search tools, LLM-oriented search APIs (Tavily, Exa, Brave, Perplexity, SerpApi), page extraction (Firecrawl, Jina Reader), citation grounding, and the cost, freshness and security trade-offs.

### Frameworks and SDKs

- [Agent Hooks and Middleware](concepts/agent-hooks-and-middleware.md): Deterministic code the harness runs at fixed points in the agent loop (before/after model calls, around tool calls, at stop) to block, rewrite, inject or observe: Claude Code / Agent SDK hooks, LangChain v1 middleware, OpenAI Agents SDK guardrails and lifecycle hooks, Mastra processors, and how they differ.
- [AutoGen and Microsoft Agent Framework](concepts/autogen.md): Microsoft's conversation-first multi-agent framework AutoGen (now archived) and its successor, Microsoft Agent Framework, which merges AutoGen with Semantic Kernel around agents and typed graph workflows.
- [Claude Agent SDK](concepts/claude-agent-sdk.md): Anthropic's Python/TypeScript library that embeds Claude Code's agent loop, built-in tools, permissions, sessions, hooks and subagents in your own process.
- [CrewAI](concepts/crewai.md): Standalone Python multi-agent framework: role-based Crews (agents, tasks, sequential/hierarchical process) for autonomy, and event-driven Flows for deterministic state and control.
- [DSPy](concepts/dspy.md): Stanford's framework for programming rather than prompting LMs: typed signatures, composable modules, adapters that compile them to prompts, and optimizers (BootstrapFewShot, MIPROv2, GEPA, BootstrapFinetune) that tune prompts or weights against a metric.
- [Google ADK](concepts/google-adk.md): Google's open-source, multi-language Agent Development Kit: LLM agents, workflow agents and (since 2.0) a graph-based workflow runtime, with sessions/state, evaluation, A2A and Google Cloud deployment.
- [LangChain](concepts/langchain.md): Open-source Python/JS framework that wraps LLM providers, tools and retrievers behind one Runnable interface and, since v1.0 (Oct 2025), centres on create_agent plus middleware running on LangGraph.
- [LangGraph](concepts/langgraph.md): Low-level, Pregel-style orchestration runtime for stateful LLM agents: typed state with reducers, nodes and edges, checkpointed super-steps, durable interrupts for human-in-the-loop, time travel and subgraphs.
- [LangSmith](concepts/langsmith.md): LangChain's hosted (or self-hosted Enterprise) platform for tracing LLM apps as run trees, evaluating them on versioned datasets with code, LLM-judge and human evaluators, and deploying LangGraph agents.
- [LlamaIndex](concepts/llamaindex.md): A Python/TypeScript data framework for LLM apps: Documents and Nodes, an ingestion pipeline, index types, retrievers, postprocessors and response synthesizers composed into query engines, plus event-driven Workflows for agents.
- [Mastra](concepts/mastra.md): Open-source TypeScript framework for AI agents and applications: agents with a provider/model router, typed suspendable workflows, layered memory, processors as guardrails, scorers for evals, and a local Studio, deployable into existing Node servers.
- [Microsoft Agent Framework](concepts/microsoft-agent-framework.md): Microsoft's open-source .NET/Python (Go preview) SDK that succeeds Semantic Kernel and AutoGen: one AIAgent abstraction over any chat client, a layered middleware/context-provider pipeline, typed graph workflows, and Azure Foundry integration.
- [OpenAI Agents SDK](concepts/openai-agents-sdk.md): OpenAI's lightweight, provider-agnostic Python/TS agent framework built on a Runner loop with agents, handoffs, agents-as-tools, guardrails, sessions and built-in tracing.
- [Pydantic AI](concepts/pydantic-ai.md): A typed Python agent framework from the Pydantic team: Agent[Deps, Output], dependency injection via RunContext, validated structured output with retry, usage limits, capabilities, durable execution engines, and test models.
- [smolagents](concepts/smolagents.md): Hugging Face's minimal Python agent library built around code actions: a CodeAgent writes Python that an AST-walking interpreter or a remote sandbox runs, with a ToolCallingAgent for JSON tool calls, any model backend, MCP and Hub tools, and hierarchical managed agents.
- [Vercel AI SDK](concepts/vercel-ai-sdk.md): Vercel's TypeScript toolkit for LLM apps: a provider-agnostic Core (generateText/streamText, Output schemas, tools, stopWhen/prepareStep, ToolLoopAgent, WorkflowAgent), UI hooks like useChat over an SSE stream protocol, and harness adapters.

### Protocols

- [Agent Authentication and Authorization](concepts/agent-authentication-and-authorization.md): How agents act for users without holding their keys: delegated vs agent identities, OAuth 2.1 in MCP (discovery, CIMD/DCR, audience-bound scoped tokens, step-up), token exchange and ID-JAG for enterprise SSO, per-user credential brokers (Arcade, Composio, Vercel Connect, Auth0, AgentCore), least privilege and audit.
