大模型为什么会“幻觉”？

一本正经地编造不存在的论文、法条甚至历史事件，并不是模型在“撒谎”，而是概率续写机制在缺乏事实锚点时的必然产物。

几乎每个深度使用过大语言模型的人，都遇到过这样的瞬间：当你询问一个冷门技术细节或某篇论文的具体出处时，AI 会用极其流畅、自信甚至带点学术腔的语气，给出一串看似严丝合缝的回答——直到你去核对原文，才发现作者、年份和页码全是凭空捏造的。

一、本质不是“查数据库”，而是“概率接龙”

理解幻觉（Hallucination）的第一步，是修正我们对模型工作方式的直觉。大语言模型内部并不存在一个结构化的“事实数据库”，它在预训练阶段学到的，是海量文本中词元（Token）之间的条件概率分布。

“模型并不知道什么是‘真’，它只知道在给定上文之后，哪一个词接在后面最像人类写出来的答案。”

在推理阶段，模型会先计算词表里每个候选词的得分（Logits），再通过 softmax(logits / temperature) 将得分转化为概率。当采样参数 temperature > 0 时，模型会按概率随机抽取下一个字，从而带来创造力，也同时埋下了偏离事实的种子。

二、幻觉最常发生的三种场景

并不是所有问题都同样容易触发幻觉。结合工程实践，最常见的诱因通常集中在以下三类：

  • 长尾事实与冷门实体：训练语料中只出现过一两次的人名、论文或 API 参数，模型权重无法形成稳固记忆，只能靠高频模式“补全”。
  • 被迫回答“不知道”的问题：传统对齐训练（RLHF）往往奖励“有帮助、完整”的回答，使模型倾向于硬着头皮作答而非坦诚拒答。
  • 多跳推理中的误差累积：自回归生成每一步都有微小的偏差概率，连续推理十步后，最初的微小猜测会被后续上下文当成“既定事实”继续演绎。

划重点

幻觉不是可以靠“调大参数量”彻底消灭的 Bug，而是生成式模型的结构性特征。降低幻觉的关键在于把模型从“记忆者”变成“阅读理解者”。

三、工程上如何把幻觉关进笼子？

既然模型天生擅长“看材料作文”而不擅长“凭空背诵”，当前工业界最有效的手段就是给模型提供可验证的外部上下文。
